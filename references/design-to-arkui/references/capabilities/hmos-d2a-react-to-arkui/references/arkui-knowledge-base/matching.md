# ArkUI 组件匹配规则

把 Figma 导出的 React/Tailwind 静态 DOM 翻译成 ArkUI 时，先从 bbox 和重复结构中归纳移动端布局，再判断它匹配哪个 ArkUI 组件。本文件只负责分析阶段的判断，不负责讲 API。

## 坐标归纳

不要机械翻译整页 absolute 坐标。先把节点按 bbox 聚类：

- 结构归纳同时结合截图、bbox 和 React DOM 层级；可见效果看截图，区域归属和拆分边界以 React 层级为准
- 相近 y、连续 x、同尺寸：横向入口、tab、Grid 行或 Row
- 相近 x、规律 y 递增：List、设置项、评论、消息、歌曲行
- 两列或多列 x 稳定、item 高度不等：WaterFlow
- 同尺寸 tile 且行列间距稳定：Grid
- 多个分类标签有选中态且明确控制下方内容页切换：Tabs
- 多个短文本胶囊/标签只表达筛选条件、排序条件或标签集合：标签流（Flex/Row/横向 List），不要误判为 Tabs
- 图片上有角标、渐变、播放量、头像压边：item 内部 Stack
- 视觉上完整的条带、卡片或文案块，如果本质是 relative 容器里的 absolute 子节点，且兄弟节点仍构成同规格重复单元，优先判定为重复区域内部覆盖层，不要直接拆成独立 section
- 某一行或某个 item 仅多出局部 absolute 覆盖层，但底层尺寸、列数、间距和父级层级仍与后续重复项一致时，优先保持它属于同一个 Grid/List 或重复集合
- 若局部覆盖层不改变重复项的尺寸、列数、间距和归属，优先保持同一个重复集合，不要单独拆区

只有不规则装饰层、图标层、复杂图片覆盖层，才保留局部 Stack + position/margin。

## 高阶组件优先识别

对每个主要区域先按下面候选识别，不要直接用基础组件手工拼同类能力：

1. WaterFlow
2. Swiper
3. Tabs
4. Grid
5. List

符合高阶组件语义且能保持视觉一致时，优先使用高阶组件。只有在高阶组件默认行为或样式实现与参考截图差异很大时，才降级为 Stack/Row/Column/Flex 或局部 .position()。

使用高阶组件时必须显式控制宽高、背景、padding、margin、间距、裁剪、安全区、选中态、indicator、barHeight 等会影响像素结果的参数。

注意高阶组件可能出现嵌套使用情况，分析时不要遗漏。例如 tabs 嵌套 list，list 嵌套 list。

## 高阶布局处理

识别到 Tabs、Swiper 等高阶组件后，要先把它们作为页面或组件的主布局容器建模，再把静态 DOM 中对应的子区域归入高阶组件的内容槽。不要先用 Stack 拼完整页面，再把高阶组件当成局部装饰塞进去。

- Figma 导出的 React 通常只有当前选中态的静态 DOM，没有真实内容切换状态。使用 Tabs 时，仍要生成 Tabs + TabContent；每个 TabContent 可以先指向当前静态 DOM 中展示出来的同一份内容 builder/组件，不要因为缺少其它 tab 的内容状态而降级为 Row/Column 或手工标签栏。
- 使用 Swiper 时同理，仍要生成 Swiper 容器；如果静态 DOM 只展示当前页，每个 slide 可以先指向当前展示出来的同一份内容 builder/组件，不要因为需要补齐 slide 容器而降级为横向 Scroll 或整页坐标堆叠。
- 使用 Swiper 时，如果原始 React 里用 SVG、图片或导出图标表现分页点、切换状态、箭头等高阶组件自带能力，应去掉这些静态图标资源，改用 ArkUI 原生高阶组件提供的 indicator、arrow、controller 等能力。这部分尽量保持和原始预览图一致，不要求完全像素级一致。
- 如果采用原生图标或状态控件，仍要显式设置尺寸、颜色、位置、显隐、点击行为和与安全区的关系，避免默认样式与参考截图漂移。只有原生能力无法还原参考图且差距很大时，才在内容槽内补局部自定义图标。

## 组件识别信号

### WaterFlow

优先用于瀑布流、错列卡片、多列不等高图片/视频/商品流。识别信号：

- 两列或多列卡片 x 坐标稳定
- 同列 y 递增，但不同列卡片高度不一致
- 卡片宽度一致，高度来自内容或图片比例
- React 代码里常见左右列 absolute 坐标或重复卡片块

从 React bbox 推导列数、列宽、列间距、行间距和每个 item 高度。不要把 WaterFlow 手工拆成左右两个 Column。

### Swiper

优先用于轮播、banner、卡片页组、引导页或带分页点的横向内容。识别信号：

- 内容区域宽度接近视口宽
- 有分页点、轮播指示器、左右滑动语义
- Figma 静态导出可能只展示当前页：一个接近视口宽的 banner 图片或 backgroundImage 面板，加一个脱离图片父节点的独立 SVG 分页点/指示器位于图片下方中间，也应优先判为 Swiper 候选

典型静态 DOM 形态：`w-[343px] h-[140px] left-[16px] ... bg-cover` 使用 `style={{ backgroundImage: 'url(...)' }}` 表达当前 banner，后面相邻出现 `<img data-svg-wrapper data-个数="5" data-位置="2nd" ...>` 这样的分页点 SVG。此时不要因为 DOM 里只有一张图、没有横向重复 slide，就降级为普通 Image 或 Stack；应把图片作为当前 slide 内容，把 SVG 指示器替换为 ArkUI Swiper 的 indicator，并根据 data-个数、data-位置 推断页数和当前页。

不要把明确分页的内容手工写成 Row + Scroll。如果只是普通横向图标栏或标签流，不要误用 Swiper。若只有单张图片且没有分页点、页数/位置、横滑语义或组件命名线索，才按普通图片/卡片处理。

### Tabs

优先用于顶部分类、二级 tab、内容切换、选中/未选中标签和下划线 indicator。识别信号：

- 多个并列文本标签，且每个标签对应一个内容页或内容分区
- 有 selected/unselected 文本样式
- 有下划线 indicator、固定 tab bar
- 标签下方存在对应内容区，且内容区不是同一列表的简单筛选结果

即使 React 是静态 DOM，没有真实内容切换状态，只要结构明显是 tab，也优先用 Tabs + TabContent。需要显式设置 tab bar 高度、indicator 宽高和位置、选中/未选中文本样式、文本间距，避免 ArkUI 默认样式造成漂移。

#### Tabs 与标签流区分

不要只因为多个标签并列或胶囊背景就采用 Tabs。先判断它们是不是页面内容切换容器：

- Tabs 必须有"页签对应内容区"的语义，点击后切换的是一组互斥内容页或内容分区；静态 DOM 里通常表现为顶部分类下方有承载对应内容的完整区域，例如不同内容类型、频道或页面分区之间的切换。
- 标签流只表达筛选、排序、话题、属性或搜索条件；点击后通常过滤同一份数据集，不改变内容容器结构。例如同一列表上方的一组筛选 chip 或排序 chip，应采用 Flex、Row、横向 List 或 Scroll + Row，下方数据仍保持原有分析结果。

### Grid

优先用于规则网格。识别信号：

- item 宽高一致或比例一致
- x/y 间距规律
- 多列图片、宫格入口、规则商品卡片
- React 中重复出现相同尺寸 tile

三列相册、作品宫格、规则图标入口不要默认写成多层 Row。使用 Grid 时固定列数、列间距、行间距和 item 尺寸；tile 内部有角标或渐变时，tile 内再用 Stack。

若覆盖层只作用于局部行或局部 item，但底层仍是统一规则宫格，优先保持一个完整 Grid，再在整体上补充区域级覆盖层。

### List

优先用于纵向重复且可滚动的内容。识别信号：

- x 坐标稳定、y 方向规律递增
- 行高固定或接近固定
- 消息、评论、歌曲、设置项、关注列表等重复行
- 内容可能超过视口

长列表用 List + ListItem + ForEach，提供稳定 key。少量静态片段可以用 Column + ForEach，但不要把明显可滚动长列表只写成普通 Column。

## 决策规则

满足下面任一条件，通常可以继续翻译：

- 铺满父容器
- 顶部锚定
- 底部锚定
- 中心浮层
- 局部叠层

这些条件只说明局部布局可以落地，不代表可以跳过高阶组件识别。顶部锚定、底部锚定、横向/纵向重复内容仍要先判断是否是 Tabs、List、Grid、WaterFlow 或 Swiper。

如果主体内容还依赖"大量相对整页像素坐标"，说明还没有从静态 DOM 归纳出结构。先按 bbox 重新分区，至少识别出顶部区域、tab、滚动内容、列表/网格/瀑布流和局部叠层，再进入 ArkUI 翻译。
