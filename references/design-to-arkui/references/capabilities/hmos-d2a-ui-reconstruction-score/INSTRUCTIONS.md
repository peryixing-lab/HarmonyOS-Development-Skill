## 目的

本能力对一组固定的参考图和实现截图完成一次评估，输出评分和可操作问题。在视觉校准流程中，两项一起返回：评分用于判断本次实现的效果，问题用于帮助父能力定位下一步修改。没有可操作问题时仍返回评分，问题列表为空。

不对顶部手机状态信息区域（如时间、信号、Wi-Fi、运营商、电池或系统指示器）和底部系统手势/小横条区域进行像素评分或作为视觉差异报告。它们仅用于推断截图对齐、安全区域处理和前景组件是否侵入系统区。

## 视觉校准调用的职责边界

由 `hmos-d2a-arkui-scoring-workflow` 调用时，固定使用“评分＋可操作问题”模式；即使调用文字只有“评分”，也不能只返回数字。这一调用方式优先于后文对输出格式的分类说明。

本能力只完成一次评分采样，采样期间不修改实现，也不自行开始下一轮。返回结果后，由父能力检查源码、实际修复、构建部署并重新截图，再发起下一次调用。

每次视觉校准调用都包含脚本评分、`compare_images` 对比和综合分析。`compare_images` 是必做的视觉分析步骤，用于辅助定位差异；“辅助”不表示可选，其结果不替代评分脚本，也不修改最终脚本分数。只有完成这些步骤并返回评分和问题，才结束本次评估。

每个问题包含稳定的 `issueId`、应用区域、证据、严重度、可能根因和应检查的组件/布局约束；只有实际读取过源码才能给出确定文件/行号，否则标为待父能力定位。`bottom region_mismatch` 等指标不能单独充当修复建议。没有可操作问题时如实返回空列表及判断依据，不为促成下一轮虚构问题；低于阈值时是否继续由父能力的修复准入规则决定。

## 工作流程

1. 判断输入是一对图片还是两个目录的成对截图。对于目录，按文件名主干（扩展名之前）配对图片。
2. 先直接审视图片。在查看数值分数之前，判断页面类型、主要区域，以及实现是全局缩放、全局偏移还是真正有缺陷。
3. 运行 `scripts/ui_score.py`（`scripts/ui_score.py` 相对本能力目录；下列命令中的完整路径相对入口 skill 根目录）生成确定性证据：

```bash
python3 references/capabilities/hmos-d2a-ui-reconstruction-score/scripts/ui_score.py reference.png candidate.png --out report
python3 references/capabilities/hmos-d2a-ui-reconstruction-score/scripts/ui_score.py pic0 pic --out report --profile mobile-app --ignore-top-px 44 --ignore-bottom-px 36
```

4. 打开生成的 `report/index.html`、拼合图、归一化图像和热力图（如有）。脚本结果仅作为辅助证据。不要让低 SSIM、热力图强度或脚本提示覆盖模型可见的 UI 相似度。
5. 调用 `compare_images` 对比本轮图片：
   - 使用本轮评分输入中的参考图和实现截图调用工具，读取返回结果，再进行后续区域分析和问题筛选。目录输入时，覆盖本次评估的配对图片，不用其中一对的结果代表其他图片。
   - 首轮基线、修复后的验证轮和最终结束轮都执行此步骤。模型自身能够看图、脚本分数已达到阈值或初步观察没有明显问题，都不省略调用。
   - 关注应用组件的位置、对齐、间距、尺寸、锚点、裁切和安全区适配。沿用现有系统区策略：系统栏自身的差异不作为问题，应用组件侵入系统区仍需诊断。
   - 用本轮工具返回结果辅助分析，不沿用上一轮的对比结论，不以工具返回的分数替换最终脚本分数。
6. 在评判前将 UI 划分为语义区域。这是强制要求；不要仅作为整体图像评估：
   - 忽略的顶部状态栏/系统区域和底部系统手势/小横条区域
   - 应用头部/导航
   - 固定标签栏/搜索/操作
   - 主内容流
   - 列表/网格/卡片/媒体区域
   - 遮罩层、对话框、底部弹出面板
   - 底部导航或底部锚定面板
7. 对每个语义区域，在允许小幅均匀缩放容差后进行比较。如果候选图整体一致地大 3-8% 或小 3-8%，但保持了锚点、层级、间距关系和可读性，则视为高相似度，不作为问题报告。仅在缩放导致布局破坏、文字裁切、可见项目数量显著变化或违反锚点时才报告。
8. 判断页面状态和可比性。不同的模态状态、路由、滚动位置或数据状态会降低可比性，但不要将布局约束失败误认为仅仅是可比性低。例如，底部面板出现位置过高是锚点问题，而非仅仅是滚动状态差异。
9. 输出本次评估结果：
   - 完成本轮脚本评分、`compare_images` 对比及上述分析后，同时返回评分和 0—3 个可操作问题，不进入仅评分分支。
   - 问题说明具体区域、可见表现、严重度、可能原因和建议检查的组件或布局约束；不要只返回 `region_mismatch` 等指标名称。
   - 没有可信的可操作问题时返回评分及空问题列表，说明判断依据，不为促成下一轮虚构问题。
   - 输出结果后结束本次调用，将是否修复以及如何继续交给父能力。

## 本轮未完成时

如果本轮脚本评分已完成，但尚未调用 `compare_images`，且本轮输入未发生变化，继续对同一组图片完成对比和分析，不重跑评分脚本、不新增轮次，也不修改实现。补齐当前轮遗漏步骤不同于复用旧图伪造新轮次；修复实现后的下一轮仍须使用新截图。已经成功取得并读取的本轮对比结果无需重复获取。

工具不可用、调用失败或没有返回可用分析时，先处理具体原因；仍无法完成则向父能力说明阻塞，本轮不能作为完整评估返回。可用分析可以是“未发现明显差异”；空问题列表不等于工具失败。不得以模型自行看图或上一轮结果代替本轮调用，不无限重试，也不为了凑问题重复调用。

## 输出模式

以下分别说明评分部分和问题部分的写法；视觉校准调用同时返回这两部分，不是任选一种模式。组合结果沿用 `references/scoring_schema.md` 的现有组合 JSON 格式。

### 评分模式

下列 JSON 是本能力返回的视觉分析结果，不是 scripts/ui_score.py 写入的 score.json。这里的 `overall` 按下方视觉分析指引计算；父工作流的阈值判定和阶段报告 `rounds[].score` 使用原始脚本文件中的 `aggregate.final_baseline_score`。两种分数分别说明，不覆盖或重写脚本文件。

返回紧凑评分及各维度分数。使用 0-100 分制，100 表示忽略顶部状态信息和底部系统手势/小横条区域后的截图级还原。

```json
{
  "overall": 84.2,
  "comparability": 0.93,
  "scores": {
    "state_match": 95,
    "region_alignment": 86,
    "fixed_component_layout": 82,
    "text_integrity": 88,
    "visual_style": 80,
    "media_fit": 76,
    "anchor_integrity": 90,
    "overlap_integrity": 96
  }
}
```

### 问题模式

返回零到三个问题。优先返回一个强问题而非两个弱问题，当没有明确可操作的问题时返回空列表。不包含状态栏/时间/电池/底部系统手势条本身的差异。将每个问题描述为可在代码中定位的 UI 问题，而非模糊的视觉不匹配。问题输出综合本轮脚本诊断、`compare_images` 返回结果和图片分析，不直接照抄工具结论，也不因需要返回问题而虚构差异。

在自然语言回复中，保持相同字段，但用用户使用的语言表述。

## 问题筛选规则

仅在问题通过以下所有关卡时才输出：

- 问题在正常截图查看尺寸下可见。
- 问题影响布局、可读性、层级、锚定、层级行为、媒体适配或有意义的视觉状态。
- 问题可能在代码中可操作。
- 问题不能仅由全局一致的缩放/分辨率差异解释。

如果没有问题通过这些条件，组合结果中的 `issues` 返回空数组；仍保留本次评分，不将整个回复缩减为只有 `{"issues": []}`。不要仅仅因为两张截图不是像素级一致就填充列表。

按以下优先顺序选择最明显的剩余问题：

1. 页面状态错误或缺失/多余的固定 UI，改变了屏幕含义。
2. 底部/顶部/中心锚点失败，包括底部弹出面板或面板未贴合预期边缘。
3. 顶部安全区失败：页面标题、返回按钮、搜索框、卡片、头像、列表首项等应用前景组件侵入真实状态栏区域。该问题即使发生在忽略评分的顶部系统区内，也必须作为 safe-area/overlap 问题报告。
4. 遮罩/层级失败，包括遮罩未覆盖预期区域、内容被裁切或内容出现在应覆盖它的层级之上。
5. 大区域整体偏移，如列表/网格/卡片区域整体上移或下移。
6. 文字完整性问题，包括截断、非预期换行、对齐错误、字号错误或标签宽度导致布局破坏。
7. 媒体适配问题，包括图片未居中、裁切错误、宽高比错误或网格图片拉伸变形。
8. 视觉样式问题，包括亮度、颜色、透明度、模糊或渐变差异。

当两个差异可见度相近时，优先选择更可能直接映射到代码的问题：锚定、父容器高度、内边距/外边距、弹性对齐、z-index/层级、文字换行、图片 `object-fit`、宽高比或透明度。

当整体屏幕视觉等价时，抑制小问题。被抑制的问题示例包括微小图标位置偏移、JPEG 压缩导致的轻微颜色差异、轻微的全局缩放差异以及不影响布局或可读性的个别文字抗锯齿差异。

## 问题措辞

以工程师能够定位相关代码的方式描述问题。

好的示例：

- "底部弹出面板未锚定在底部；其底边远离视口底部。"
- "网格内容起始位置过低，导致第一行未被设计中的顶部遮罩覆盖。"
- "搜索输入框过窄或内边距过大，导致查询文字被裁切。"
- "主媒体图片在其容器内向右偏移；检查图片居中或 `object-fit`。"

避免：

- "这个区域不一样。"
- "实现与设计不匹配。"
- "颜色不对"而未指明区域和可能原因。
- 任何关于时间、电池、信号或其他手机状态信息的问题。

## 评分指引

以模型可见的区域推理作为主要判断依据。使用脚本的 `final_baseline_score`、`scale_tolerant_baseline_score`、热力图和条带指标作为辅助证据。`deterministic_baseline_score` 仅作为原始证据。当原始像素指标较低但屏幕是相同 UI 且仅有全局缩放/分辨率差异时，在视觉分析 `overall` 中忽略该差异，除非它导致具体的布局失败，如裁切、重叠、锚点错误或可见项目数量显著不同；该处理不影响脚本自身的 `final_baseline_score`。

对于移动应用截图，推荐的默认权重为：

```text
overall =
  state_match * 0.10 +
  region_alignment * 0.18 +
  fixed_component_layout * 0.20 +
  text_integrity * 0.12 +
  visual_style * 0.12 +
  media_fit * 0.08 +
  anchor_integrity * 0.12 +
  overlap_integrity * 0.08
```

在加权评分后应用扣分：

- 关键固定元素缺失或多余：-8 至 -18
- 模态/页面状态错误：-10 至 -25，并降低 `comparability`
- 底部/顶部锚点失败：-6 至 -15
- 应用前景组件与真实状态栏重叠：-8 至 -18，并降低 `overlap_integrity`
- 文字被裁切、重叠或不可读：-5 至 -12
- 主要区域整体偏移：-4 至 -12
- 媒体裁切/宽高比明显错误：-3 至 -8
- 纯颜色/透明度差异：-2 至 -7，除非遮挡内容
