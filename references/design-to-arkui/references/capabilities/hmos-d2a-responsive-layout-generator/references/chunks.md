# 分块生成策略

## 概述
当输入组件数量较多时，一次性生成完整的响应式DSL会导致输出过长，超出模型生成能力限制而产生截断或失败。分块生成策略通过将长输出拆分为多个小块，逐块生成后再回填合并，确保生成过程的稳定性。

> 本文件只定义分块策略、约束与断点恢复规则。DSL 的确切数据形状以 `references/dsl-schema.md` 为准；流程口径以能力 `INSTRUCTIONS.md` 步骤 4–6 为准。

## 1. 触发阈值

| 组件数量 | 生成模式 | 说明 |
|---------|---------|------|
| 1-7 | 单次生成 | 输出长度可控，一次性生成完整DSL |
| 8-14 | 分块生成（2块） | 每块约4-7个组件 |
| 15-21 | 分块生成（3块） | 每块约5-7个组件 |
| 22-28 | 分块生成（4块） | 每块约5-7个组件 |
| 29-35 | 分块生成（5块） | 每块约5-7个组件 |
| 36+ | 分块生成（⌈N/7⌉块） | 每块不超过7个组件 |

**判断公式**：
- 如果组件数 < 8：单次生成
- 如果组件数 ≥ 8：分块数 = ⌈组件数 / 7⌉（向上取整，确保每块不超过7个组件）

## 2. 分块原则

### 2.1 分块维度：按组件分组
- **优先按布局分组（Y坐标分组）分块**：同一行/同一布局组的组件放入同一块，避免割裂布局语义
- **组内组件数限制**：每块不超过 7 个组件
- **组间合并**：如果某组组件数不足 3 个，与相邻组合并（合并后不超过 7 个）

### 2.2 分块内容
每个分块文件 `chunk_N.json` 保存第 N 块组件的响应式配置集：

- `chunkMeta`：`chunkIndex`（从 1 开始）、`totalChunks`、本块 `componentIds`、来源布局分组名
- 每个组件一条记录：组件 id + 该节点的 `responsive` 配置（含断点覆盖 `breakpointOverrides`）

字段名与结构必须符合 `references/dsl-schema.md`，不得发明字段。

### 2.3 骨架
首次分块前，先在上下文中生成完整嵌套树骨架：仅包含 metadata、page、layoutStrategy、breakpoints 框架，`ui.children` 为空数组（结构见 `references/dsl-schema.md`）。骨架不单独落盘，作为后续回填的底稿。

## 3. 分块生成工作流

```
输入DSL（N个组件，N≥8）
  │
  ├─ 步骤4a：判断分块数量 → ⌈N/7⌉ 块
  ├─ 步骤4b：按Y坐标分组，确定每块包含的组件
  ├─ 步骤4c：生成嵌套树骨架（ui.children 为空数组）
  ├─ 步骤4d：逐块生成 chunk_N.json
  │   → 仅输出第 N 块组件的 responsive 配置
  │   → 写入 {projectRoot}/.deveco/{saveName}/chunk_N.json（每块落盘即完成标记）
  │   （重复直到所有分块完成）
  └─ 步骤4e：所有分块完成 → 按 id 将各块 responsive 配置回填嵌套树

步骤5：断点适配优化（对回填后的完整 DSL 整体优化）
步骤6：输出最终响应式 DSL 文件
```

## 4. 分块生成关键约束

### 4.1 每块输出的严格限制
- **每块仅包含本块组件的响应式配置**，不重复输出骨架信息
- **每块输出格式**：必须是合法 JSON，可直接写入文件
- **每块组件数上限**：不超过 7 个组件，超出则需进一步拆分
- **组件 id 唯一性**：不同分块的组件 id 不可重复
- **引用完整性**：分块中的 breakpointOverrides 引用的断点名称必须与骨架中的 breakpoints 一致

### 4.2 上下文保持
- 生成每个分块时，必须由调用方上下文直接提供以下信息：
  - 骨架的 layoutStrategy（确保组件 responsive 配置与布局策略一致）
  - 容器尺寸信息（用于计算百分比等响应式值）
  - 已生成分块的组件 id 列表（避免重复）
  - 本块组件在原始输入 DSL 中的绝对位置信息

### 4.3 容错与恢复
- 如果某块生成失败（截断/格式错误），仅重新生成该块，不影响已完成的其他分块
- 以 `.deveco/{saveName}/` 下已存在的 `chunk_N.json` 为完成依据：恢复时跳过已有块、仅补生成缺失块，不重复生成，不重命名已有产物
- 每块生成后立即做 JSON 格式验证，确保可解析

## 5. 回填与合并规则

### 5.1 回填嵌套树
- 所有分块完成后，按组件 id 将各块的 `responsive` 配置回填到嵌套树骨架的对应节点
- 保持组件在原始 DSL 中的出现顺序

### 5.2 断点覆盖合并
- 各分块的断点覆盖按节点 id 以 `breakpointOverrides` 精确挂载（见 `references/dsl-schema.md`）
- 同一断点名称的调整合并到该断点下，不得互相覆盖丢失

### 5.3 warnings 和 suggestions 合并
- 各分块可能产生各自的 warnings 和 suggestions
- 合并时去重后追加到最终 DSL 对应字段

### 5.4 回填验证
- [ ] 回填后组件总数 == 原始输入组件总数
- [ ] 所有组件 id 无重复
- [ ] 所有断点引用有效（breakpointOverrides 中的断点名称在 breakpoints 中存在）
- [ ] JSON 格式合法

## 6. 中间文件结构

```
{projectRoot}/.deveco/{saveName}/
├── chunk_1.json            # 分块1（该块组件的响应式配置）
├── chunk_2.json            # 分块2
└── ...
```
